1. Ajustes al Proyecto APT: Dificultades, Facilitadores & Retroalimentación Indicador 1 · 10%

1.1 Diagnóstico de Dificultades Técnicas y Operativas

Durante el ciclo de desarrollo e iteración del MVP de PlayMatch, el equipo se enfrentó a desafíos críticos de diseño, arquitectura y experiencia de usuario que demandaron un análisis de causa raíz y ajustes sistemáticos:

  • Degradación de Latencia e Interacción (INP en 240 ms): En las pruebas preliminares con Chrome DevTools, el selector de filtros de juegos arrojaba un Interaction to Next Paint (INP) inadmisible de 240 ms. La causa residía en la transición de sombras neumórficas exteriores a interiores (box-shadow inset a outset), obligando a Chromium a rasterizar por CPU el árbol DOM en lugar de componer por GPU.
  • Sobrecarga de Renderizado por Desenfoque Gaussiano Extremo: La atmósfera visual inicial utilizaba orbes flotantes con filter: blur(120px) y texturas de 130vmax rotando de forma continua. Esto saturaba el pipeline de renderizado en equipos con tarjetas integradas, provocando caídas a 25-30 FPS y micro-tirones (stutter).
  • Colisión Ergonómica en Formularios de Acceso: Los iconos de usuario y contraseña se ubicaban con posicionamiento absoluto al interior de las cajas de texto (pl-10). Al tipear cadenas largas o al dispararse el autocompletado nativo del navegador, las letras se superponían directamente sobre los iconos SVG, degradando la usabilidad.
  • Fatiga de Contenido por Acumulación de Componentes: La versión previa desplegaba en un único scroll vertical kilométrico el feed de jugadores, los 12 filtros de juegos, las estadísticas de afinidad, las tarjetas de torneos y las llaves de eliminación, saturando cognitivamente al usuario.
  • Disonancia Tipográfica y Estética: El uso extensivo de fuentes monoespaciadas (JetBrains Mono) transmitía la sensación de consola de código o terminal de inteligencia artificial, alejándose del lenguaje visual deportivo de los esports AAA.

1.2 Factores Facilitadores Identificados

Frente a estos obstáculos, el equipo capitalizó facilitadores técnicos de última generación:

  • Arquitectura de Islas de Astro 4: Permite renderizar estáticamente el esqueleto HTML (cero JavaScript innecesario en el cliente) e hidratar exclusivamente los componentes que requieren interactividad (client:load y client:idle).
  • Aceleración por Hardware de Chromium: Los motores de renderizado modernos delegan la decodificación de video MP4 (H.264/NVDEC) directamente al hardware de video dedicado, manteniendo el consumo de CPU por debajo del 1%.
  • Testing Automatizado Continuo: La suite test_design_system.py permitió ejecutar regresiones automatizadas en cada cambio, verificando 0 emojis, compilación de clases CSS críticas y estructura semántica.

1.3 Ajustes Metodológicos y Técnicos Implementados (Cierre del Ciclo)

Resolución Integral Aplicada
  1. Desacoplamiento en Ventanas Propias: Se segmentó el dashboard en 3 vistas dedicadas (Operadores & Perfiles, Torneos & Brackets, Arquitectura Técnica) controladas por un conmutador HUD neumórfico sincronizado con el Navbar superior.
  2. Iconos Exteriores en Cajas Tácticas: Se extrajeron todos los iconos de los formularios a bloques exteriores independientes (w-10 h-10), eliminando al 100% cualquier riesgo de colisión con el texto ingresado.
  3. Identidad Carmesí & Tipografía Humana: Se adoptó la paleta Crimson Red (#FF2A4D) sobre fondo Obsidian Carbon (#07080A) y se implementó la familia Rajdhani para métricas de esports junto a Plus Jakarta Sans para lectura humana.
  4. Orbes Nativos de Hardware: Se reemplazó el filtro Gaussiano por radial-gradient evaluado en un único ciclo de fragment shader, estabilizando la tasa de refresco en 60–120 FPS.

-- Extracto del Modelo Relacional de PlayMatch (PostgreSQL 16)
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    username VARCHAR(32) NOT NULL UNIQUE,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    country VARCHAR(3) DEFAULT 'CHL',
    karma_score NUMERIC(3, 2) DEFAULT 5.00 CHECK (karma_score BETWEEN 0.00 AND 5.00),
    total_reviews INT DEFAULT 0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE gamer_profiles (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    game_code VARCHAR(32) NOT NULL, -- 'valorant', 'cs2', 'deadlock', 'lol'
    gamertag VARCHAR(64) NOT NULL,
    current_rank VARCHAR(32) NOT NULL,
    preferred_role VARCHAR(64),
    schedule_preference VARCHAR(16) DEFAULT 'noches',
    UNIQUE(user_id, game_code)
);

CREATE TABLE tournaments (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(128) NOT NULL,
    game_code VARCHAR(32) NOT NULL,
    max_teams INT NOT NULL DEFAULT 8,
    status VARCHAR(16) DEFAULT 'open' CHECK (status IN ('draft', 'open', 'ongoing', 'finished')),
    format VARCHAR(32) DEFAULT 'single_elimination',
    start_date TIMESTAMP WITH TIME ZONE NOT NULL
);

4. Precisión del Lenguaje Técnico Disciplinar Indicador 4 · 5%

El proyecto hace un uso estricto y riguroso de la terminología de ingeniería de software, arquitectura de sistemas y ciencias de la computación:

Término Técnico Definición & Aplicación en PlayMatch
Islands Architecture Patrón arquitectónico introducido por Astro en donde el documento HTML se genera estáticamente en el servidor (SSG) y las zonas dinámicas son pequeñas "islas" independientes que cargan JavaScript únicamente al entrar en viewport o requerir interactividad.
Hydration Mismatch Inconsistencia temporal entre el árbol DOM pre-renderizado en el servidor y el árbol generado en el cliente por el framework reactivo. En PlayMatch se previene aislando el AuthGate mediante conmutación CSS (display: block / none) garantizando cero descarte de nodos en caliente.
Interaction to Next Paint (INP) Métrica de Core Web Vitals que mide la latencia de respuesta ante cualquier interacción de usuario. Se redujo de 240 ms a menos de 16 ms mediante React.useTransition y pre-cálculo de afinidades en tiempo lineal \(O(N)\).
GPU Compositor Thread Hilo de ejecución del navegador que procesa transformaciones espaciales y opacidad de capas aisladas sin delegar el repintado al hilo principal de CPU, alcanzando tasas estables de 120 FPS.
Integridad Referencial DDL Reglas de restricción relacional (Foreign Keys, cláusulas ON DELETE CASCADE y restricciones CHECK) aplicadas en el motor PostgreSQL para evitar huérfanos o inconsistencias de datos.
